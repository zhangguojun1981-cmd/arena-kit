# VPS Deck 面板使用指南（阶段 C）

阶段 C 的源码开发与服务器侧自动化验收，不等于手机已安装新版本。手机上的版本、源码目录与签名升级仍须单独核验。请勿卸载旧版或清除数据。

## 通用操作顺序

连接已保存的服务器 → 刷新资源列表 → 选择实际资源 → 填表/预览 → 核对服务器与目标名称 → 明确确认 → 查询任务 → 刷新实际资源。

- SSH 主机指纹必须保持匹配，不会自动接受改变的指纹。
- `sudo -n` 只使用已有免密授权；不会提交密码或配置 sudo。
- C 阶段任务独立运行在远端 systemd 中。离开 App 不会取消任务；后台停止自动轮询，回到前台再查询。断线、超时、未知状态不代表失败或成功，不自动重试变更。
- 任务成功仅代表相应的检查通过。容器运行不代表业务健康，软件包安装不代表服务启动或公网可达。

## 服务与容器

从真实列表选择服务/容器，在详情中操作。容器删除仅支持已停止容器，不使用强制删除或删除卷参数。容器可写层会丢失；命名卷保留不等于数据已有备份。

创建容器使用表单管理的独立 Compose 项目。镜像拉取与部署分别确认；重建、恢复配置检查原项目是否发生外部变化。恢复的是配置与保留镜像，不是数据库或卷中的业务数据。外部清理镜像可能使旧配置无法恢复。

## Compose

已有容器的项目从 Compose 标签发现。尚未部署的目录可通过“登记已有目录”添加：填写项目名、原始工作目录、按原顺序排列的配置文件绝对路径。

登记只校验并保存路径，不改写 YAML、不拉取、不启动容器。同名不同路径的项目拒绝覆盖。没有配置文件时，先通过文件页创建或编辑。详情中的文件入口跳转到原文件目录；保存后返回项目重新预览配置，再单独确认应用。

`pull`、`up`、`stop` 是三个独立操作。不会隐式运行 Dockerfile 构建；只有 build、没有镜像的项目不能直接应用。复杂项目请先检查完整 YAML，包括挂载、权限、环境与端口。

## 环境与 Docker 安装

安装适配器目前限定 Debian 12；Docker 官方源向导限定 amd64/arm64。需已有 Python 3 与适用的 root/明确 sudo 授权。

原生 Nginx、PHP-FPM、PostgreSQL、MariaDB、Certbot 等组件：先刷新索引（若需要），预览依赖，再确认安装。拒绝卸载计划，保留原配置，不承诺回滚包管理器变化。

Docker 向导分四步，每一步都要单独确认：

1. 安装 HTTPS CA 与 GnuPG 前置组件。
2. 配置 Docker 官方 Debian 12 stable 源：验证公钥指纹，使用独立源与密钥文件，不覆盖其他源。检测到冲突运行时或其他 Docker 源时拒绝自动迁移/重复添加。
3. 使用页面上方按钮刷新 APT 索引。
4. 预览并安装 Docker Engine、CLI、containerd.io、Buildx、Compose 插件；核验包状态和 CLI 版本。

安装脚本可能启动服务并改变网络规则。Docker 发布端口可能绕过 ufw；此版本不会替你配置防火墙。安装后到服务面板检查 Docker，再到容器页刷新验证；不要把包安装成功当成业务验收。

## 数据库

数据库认证与 SSH 认证分离。选择原生实例或现有数据库容器，再输入该实例的数据库身份。用户管理限制在 `app_` 应用账号，不接管管理员账号。

建库、创建用户、直接授权/撤权、密码变更、逻辑备份与恢复均独立确认。恢复/删除数据库前必须生成可校验的安全备份并记录恢复标识。任务失败可能已部分生效；不会自动回滚或重放。

备份不包含完整实例角色与所有权限；MySQL 非事务表不保证一致性。撤销直接授权不代表移除了继承或 PUBLIC 权限。恢复后还需检查业务数据和访问权限。

密码与环境输入不写进普通任务请求记录，而放入权限受限的敏感输入文件；执行器读取后删除。启动前异常仍可能留下私有输入，需要管理员核查。托管项目自身运行所需环境仍保存在远端受限配置中。

## 网站、文件和高级诊断

复杂既有 Nginx 配置不会被静默改写或接管。新站点/托管操作与原始文件修改分开；配置检查、重载与 HTTP 验证各有边界。公网 ACME 签发、DNS、端口可达与无人值守续期需要独立外部验收。

普通操作请用原生资源面板。高级页面只保留原始只读诊断，以及明确确认的非托管 Nginx 重载、主机重启等操作。重启后的断线不能作为重启成功，必须重连核对运行状态。

## 仍需独立核验

手机同签名原位升级、已存 SSH 密钥和主机指纹保留、实机页面操作与源码下载目录校验。防火墙管理不在本阶段范围内。生产服务器不会被用来做破坏性或状态变更回归。
